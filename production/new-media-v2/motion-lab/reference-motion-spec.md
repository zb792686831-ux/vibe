## 2. 三类运动的实际语法

### A. 实物入场：接触之后收敛，文字不跟着晃

**事实。** 1.4s 的骰子仍在翻转并有残影，1.567–1.9s 可见朝向快速变化和地面接触；2.067–2.567s 倾斜幅度逐步收小；2.733s 后已接近稳定立方体，2.9–3.2s 仍有细微转动但构图不再大幅变化。地面细椭圆、碎屑／微光和投影与接触位置相关联。下方句子在 1.4–2.9s 基本固定，3.067s 左右才开始退去。

- 骰子宽约画面 15%–20%，高约 25%–33%；主体在中间略偏下，左右大面积暗部。
- 底部句子的基线约在高度 86% 一带，字高约高度 4%–5%；主体和文字不是一起滑入／一起弹跳。
- 可见的是“较快的翻转 → 接触／小回弹 → 衰减落定 → 稳态阅读”，不是匀速旋转后突然停机。

**本题可迁移规格。** 红心的激活或信号落点用短促接触反馈；位移到达后，旋转或微缩放允许多延迟 0.10–0.18 秒才收敛。不能把整颗红心、字幕、背景同时套一条 1.3 秒缓动。无需复制骰子、碎屑或它的具体轨迹。

### B. 图形与标题转场：先撤旧焦点，再形成新焦点，最后补关系

**事实。** 5.6–6.1s 的线框骰子与周围 `1/6` 已可读；6.267–6.433s 旧底部句子模糊退出；6.6s 图形仍在局部光雾中可辨。6.767–7.267s 新标题从局部模糊、点尘逐步清晰，文字位置近似稳定；7.433s 主标题基本稳定。7.6–8.1s 才接着描出下方曲线和补入较小说明。它没有让主标题、曲线、说明同时完成淡入。

- 主标题约占宽度 50%–55%，字高约高度 13%–16%，中心在画面中部；比图内注释大数倍。
- 曲线和小字属于第二、第三阅读层，等主标题成立后才补足。
- 光效集中在旧主体转译为新主体的过渡位置；清晰后明显减弱，避免整段持续闪烁。

**本题可迁移规格。** 用同一颗红心／信号点保持身份，过渡时先减弱手机外框，再让信号点沿曲线到下一构图的输入位置。光晕只在“红心变为信号”“信号被记录”的事件附近短暂出现。参考此处有较亮的光雾，但用户本版要求纯黑与暗波点，因此**不复制整屏泛白**，仅用局部、低透明度暖光作为事件反馈。

### C. 图解生长：父节点到子节点，得到结果之后再读结果

**事实。** 59.0s 的右侧树图只展开到少数节点；59.2–60.8s 按层向右增加分支和节点。父分支在先，新一层从已经成立的节点继续生长。约 61.0–61.2s 最右结果逐步出现，底部句子转入“16种未来”的解释。61.4–62.0s 红色路径从起点贯通到右下的特定结果，结果对照随之明确。62.0–63.2s 布局基本稳定，观众获得比较和阅读时间。63.6–65s 焦点进一步偏向右侧树图，左侧旧比分退暗，树图保留，并非全屏清空再加载下一张图。

- 图解区域约占宽度 55%–60%、高度 45%–50%，主体在中右部；左侧旧证据较小且逐步退暗。
- 底部解释句继续在高度 86% 左右稳定居中。旧句先退，新句在信息成立的阶段逐步变清楚，没有一直追着图形移动。
- 生长与读句有分工：约两秒展开，约一秒强调路径，再留一秒以上比较；它不是一条线足足慢画五秒，也不是所有线一起出现后让粒子空转。

**本题可迁移规格。** 先显示“停留／重看／点赞”的行为源；到“被平台记录，变成信号”时，才发出沿路径行进的输入脉冲；脉冲抵达记录点后，该节点才亮起；到“成为推荐的参考”时，再展开输出支路。新图不能提前展示尚未说明的结果。

## 3. 当前完整成片的实际问题

这些问题来自本次连续抽帧和 `src/new-media-v2/final/NewMediaFinal.tsx`、`Diagrams.tsx` 的实际实现，不是只看封面作出的判断。

1. **阅读先于图形成立。** `Caption` 在 0.55s 完成淡入，图解却叠加 `VisualGroup` 0.8s、`FinalDiagram.enter` 1.35s 和各条路径自己的 1–3s 渐显。当前 39.0s 实际输出近黑，39.5s 只有淡淡图标，40s 后线图才开始可辨。观众先读到整句，再等待图解追上，不容易把动词与动作连起来。
2. **结果早于输入。** `signals` 中央节点在 local 1.5–2.7s 出现，三条输入线到 local 3.2–3.6s 才完成；输出支路 local 2.3s 已开始。当前 41.5s 已看到结果方向分叉，字幕仍是“停留、重看、点赞……”。应由“输入到达”驱动记录点和输出，不让它们各自按独立时钟先行出现。
3. **图形身份在场景边界丢失。** 当前 34.5–36.5s 红心缩成非常小的点，36.3–39s 虽描出一条局部曲线，但在 39s 被整体丢弃；下一组图重新从别处淡入。48s 又整体近黑。局部动作没有实际把观众带进下一张图，视觉更像多张模板轮流显隐。
4. **大部分运动共用一个速度性格。** 主场 `e()` 使用同一条 `cubic-bezier(0.4,0,0.2,1)`；图解大量 `progress()` 使用同一条 `cubic-bezier(0.2,0.72,0.22,1)`。即便空间路径是三次贝塞尔，位移、透明度、线条和物件仍同时起步、同时减速。空间曲线不等于有物理层次的时间曲线。
5. **循环粒子没有解释事件。** 信号点的 `phase` 取全局时间循环，与“哪一次停留触发、何时到达、到达后累计”没有绑定。当前 43–47s 大部分骨架已经完成，少量点仍以相似速度漂动；它增加了动的表象，却没有新增可理解的反馈。
6. **短句也消耗同样的入场时间。** 当前每句固定 0.55s 淡入、0.75s 微移，但 31–32.45s 的短句只有 1.45s；入场占比与 3.5 秒长句差别很大。慢不是所有事件都拉长。应减少字幕无意义的入场，把时间让给稳定阅读和关键动作。

## 4. 建议本轮样片：全局 28–48 秒

该 20 秒同时覆盖：一次具象物件反应、一次消失／保留的对照、一次跨构图转译、一次图解因果。它比 39–59 秒更能检验“物件如何变成图解”，而不是只检验三张线图模板能否依次出现。

保持已批准的 8 条句子和原时间段不变：

| 全局时间 | 原句 | 拟验证的运动与停留 |
| --- | --- | --- |
| 28–31s | 顺手，点亮一颗红心。 | 手机已经在场；红心在 28.1–28.7s 完成短距离弧线／激活，接触后微小回弹，不和字幕一起缓慢飘入。28.9–31s 明确保持可读稳态。 |
| 31–32.45s | 然后，划走。 | 31.2s 起屏幕内容上移，前半程加速、随后迅速离开，不给整个手机套完整缓慢淡出；手机外壳保留，红心不跟内容一同消失。动作主要在约 0.65–0.8s 内完成。 |
| 32.45–34.1s | 视频过去了。 | 空屏／退出后的对照保持约 0.6–0.8s，再减弱手机外壳；红心仍清楚可见。这里的静止是叙事，不用粒子填空。 |
| 34.1–36.3s | 你的反应，留下了。 | 红心 0.35–0.5s 收成一个仍可读的信号形态，直径约 32–44px，而非几乎不可见的 12px；留至少 0.8s 稳态，观众先看懂“保留”。 |
| 36.3–39s | 刚才那几秒，去了哪里？ | 同一信号沿一条弧线移向下一图的“点赞”输入位置，轨迹尾部适度保留；不是另造一颗无关的点。临近 39s 只补入下一构图的两个其余输入锚点，保持信号身份和视线连续。 |
| 39–42s | 停留、重看、点赞…… | 三个行为源以约 0.35–0.45s 间隔依次被激活；文字位置稳定，三个源激活后留约 1s 比较。不提前展开完整推荐结果。 |
| 42–45.5s | 它们被平台记录，变成信号。 | 输入脉冲依次沿路径走向记录点，单次传输约 0.65–0.9s；抵达之后才出现微光／记录点状态变化，最后一次抵达后保留 0.7–1s 稳态。每条路可以有不同路程和速度，但不随机漂动。 |
| 45.5–48s | 成为推荐的参考。 | 从已成立的记录点展开两到三条输出支路，末端结果在路径到达后出现；约 47.1s 前完成，剩余约 0.9s 完整读图。末帧仍保留结构，不以全黑作为样片结尾。 |

以上是样片的具体动作建议，不是对参考作者工程参数的复刻。允许按实际动画结果微调动作子区间，但不动文案措辞、字幕段落和 BGM 对齐。

## 5. 可直接实施的画面与运动约束

### 构图与字级

- 保留用户指定的“中心主体＋下方居中说明”排版。主视觉活动区约 `x=350–1570、y=130–740`；主字幕稳定在当前 `y≈846` 区域，底部至少保留 100px 安全空间。
- 保留当前已选宋体主字幕，建议继续使用现有 84px，避免本轮同时换字体、改字号和改运动而失去比较依据。图内辅助标签保持约 32–40px；它们是分类，不再承担另一套长句。
- 手机宽约 420px（画面宽 22%）；转入图解后结构可占宽 55%–65%，不能让单个微点在数秒内成为几乎唯一可见内容。信号点可以小，但应有可辨的源、目标或留痕提供尺度。
- 主线继续遵循用户要求的 6–9px；暗部辅助线可降至约 3–4px 和较低透明度，避免所有线一样粗、一样亮。米白正文、暖金信息、红心局部红不改为新的大面积色彩系统。
- 只在纯黑和暗色浅波点之间交替；波点运动低于前景动作，不引入浅底、全屏闪白或多种新背景。

### 时间曲线必须按动作角色区分

- **划走／离开**：短等待、明显加速、快速越界；不要在越界前慢慢刹到零。可在出画后再结束状态。
- **物件落位／激活**：较快到达，最后 10%–15% 路程减速，随后 0.10–0.18s 小幅角度／尺寸收敛；只允许一次很小回弹。
- **线条生长**：按路径弧长推进，父段先到节点，子段随后开始；不使用一段全图统一 opacity 代替生长。
- **信息传输**：每个脉冲有明确发射、行进、到达、结果四个状态；不能在路径尚未成立时，沿整条路径同时摆满循环粒子。
- **文字**：默认 0.16–0.24s 清晰完成后稳定，不持续上下漂动；最多给新句一次很小的显现变化。需要强调的词用颜色／局部明暗，不让整句反复缩放。
- **稳态**：每一解释单元必须有 0.7–1.2s 前景几乎不改变的窗口；背景可以呼吸，但不要让“停留”变成机械的全画面悬浮。

### 遮罩、光效与音效的因果

- 手机内容使用屏幕内部遮罩，划走时只裁切内容，不把外壳、红心和字幕一并擦除。
- 线条揭示的 mask 与正在前进的端点保持一致；端点抵达之前，结果节点不得提前亮起。
- 光效只跟随“激活／被记录／到达”的事件，不做全场常驻大光圈。局部反馈可约 0.08s 起、0.25–0.4s 衰减，半径随事件轻扩后回落。
- 音效只建议落在红心激活、划走、记录点到达、推荐支路收束等少量节点。可参考既有客观起音表中 28.725s、31.648s、33.244s、45.736s 附近的时间，但必须以新动作的实际到达时刻为准。这里只作视听对齐建议，没有人工听审。
- 沿用已核实的用户 BGM 偏移：参考／全局时间 `t` 对应用户 BGM `t+0.048s`；本样片用 BGM 28.048–48.048s。音乐不换曲、不变速。音效只作为重点反馈，不能每条线、每个字都叠加声音。

## 6. 样片验收应检查连续过程

1. 按正常速度看完整 20 秒：不暂停时，能否看懂红心如何变成被记录的信号、再成为推荐参考；不能只问截图是否漂亮。
2. 逐帧检查事件前后：路径抵达前有没有结果先出现，遮罩有没有切掉不该消失的对象，物件跨构图是否保持身份。
3. 检查每条字幕出现后的 0.7–1.2 秒：重要图形是否已经成立，字幕是否稳定，读图是否还在等下一层慢慢淡入。
4. 检查 39s、42s、45.5s 和 48s 附近：不出现因所有层同时淡出而造成的近黑断接，不把两个语义步骤塞在一句话出现之前。
5. 交付真实 MP4，并从该 MP4 导出 0.2–0.5s 连续联系表作内部复核；仍不能以三张关键帧、技术解码通过或工具图像卡片代替用户看到连续样片。
